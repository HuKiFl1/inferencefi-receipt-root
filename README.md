# inferencefi-receipt-root

An independent off-chain reference implementation and test companion for
**Inference Finance**, a Solidity AMM prototype on HyperEVM testnet (chain
998). Inference Finance is unaudited and uses TEST mocks only. It integrates
the **FLOP Network** through receipts, escrow and channels.

This repo is a **proposal for decision IF-D8**: should the Uniswap-v4-style
hook's `jobId` be a Flop receipt root? The proposal is **pending the spec
owner and palmer**. Nothing in it is adopted, deployed or audited.

**Short answer:** yes, but the jobId should be a domain-separated commitment
to the root, not the raw root. The full argument is in [DESIGN.md](DESIGN.md).

## What is here

| Path | What it is |
|---|---|
| [`DESIGN.md`](DESIGN.md) | The design note: receipt leaf, hashing (blake2b on FLOP, keccak on the EVM, dual commitment), Merkle tree, root to jobId, epoch binding and nullifiers, OmerMinter redeem vs reclaim under TCLK rules, trust assumptions, threat model and open questions. |
| `src/` | Pure TypeScript reference with no runtime dependencies. All amounts are `bigint`; there are no floats. It covers leaf encoding, clean-room keccak-256 and BLAKE2b, the tree, proofs and verification, jobIds and nullifiers, a root registry, models of AgentRewards (IF-F11) and OmerMinter (IF-F12), the Flop payout waterfall and watcher audits. |
| `vectors/receipt-root-v1.json` | Deterministic test vectors generated by `scripts/`. Every scenario expectation is written by hand in `scripts/vectors.ts`, and generation fails if the models disagree with it. |
| `foundry/test/ReceiptRootVectors.sol` | A Foundry **test template**, not a product contract. It replays the vectors through hooks the spec owner implements. It ships with a test-only mock verifier that must pass and 15 deliberately broken verifiers that must fail. |
| `tests/` | vitest unit tests, fast-check property tests (one block per threat, T1–T11), a vector replay, and a mutation check. |

## Running it

Requirements: Node.js 20 or newer. For the Solidity template you also need
[Foundry](https://book.getfoundry.sh/); it fetches solc 0.8.39 on first run.

```bash
npm ci                  # or: npm install
npm test                # vitest: unit, property, vector replay and mutation tests
npm run typecheck
npm run build           # emits dist/
npm run vectors         # regenerates vectors/receipt-root-v1.json (output is byte-identical)
npm run forge           # same as: cd foundry && forge test
npm run check           # typecheck + vitest + forge
```

Property tests run 100 cases each by default. Run more with
`PROPERTY_RUNS=1000 npm test`.

`tests/vectors.test.ts` regenerates the vectors in memory and fails if the
committed JSON differs, so the JSON cannot drift from the code.

## The mutation check

`tests/mutation.test.ts` applies 36 single-point bugs to a copy of `src/`,
one at a time. Examples: a missing leaf or node prefix, duplicating the odd
node, ignoring leftover siblings, no index bound, a jobId or nullifier missing
a domain field, an unbound `leafCount`, a timeout off by one, payer senior to
lender, reclaim against any root, and a redeem that settles twice. For each
mutant, the test replays the full vector file plus a few targeted checks and
requires the run to fail. The unmutated copy must pass the same run.

The Foundry template does the same on the Solidity side with its `Broken*`
verifiers.

## Using the Foundry template

1. Implement `IReceiptRootHooks` (pure encoding, hashing, proof and payout
   functions) and `IReceiptSystemHarness` (an adapter over your registry,
   AgentRewards and OmerMinter that returns status codes instead of
   reverting).
2. Add a test contract:

   ```solidity
   contract SpecOwnerVectorsTest is ReceiptRootVectorsTest {
       function _hooks() internal override returns (IReceiptRootHooks) { return new MyHooks(); }
       function _newHarness() internal override returns (IReceiptSystemHarness) { return new MyAdapter(); }
       // false: compare accept/reject only, not the exact status code
       function _strictCodes() internal pure override returns (bool) { return true; }
   }
   ```

3. Run `forge test` in `foundry/`. The template reads `../vectors` through
   Foundry's JSON cheatcodes and does not depend on forge-std.

## What this does not solve

- **There is no on-chain FLOP credit token and no FLOP light client on the
  EVM.** Roots reach HyperEVM through a k-of-n attester set. The attesters are
  trusted for correctness, completeness and liveness. Watchers can detect
  their faults off-chain (`auditSnapshot`, `auditTransition`), but the EVM
  cannot yet act on that evidence. See DESIGN.md §4.3 and §9.
- The Inference Finance contracts are owned by another team and are not
  public. The models here follow spec items IF-F11, IF-F12 and IF-D8 only.
  The contract-facing parts are proposals, and DESIGN.md §12 lists the
  questions for the spec owner.
- FLOP details that depend on the not-yet-final Yellow Paper are marked
  **[YP]** in DESIGN.md.

## Clean room

All code is original. keccak-256 is implemented from NIST FIPS 202 and
BLAKE2b from RFC 7693. `@noble/hashes` (MIT) is a dev-only dependency, used
as an independent oracle in the hash tests. The tree follows RFC 6962/9162.
DESIGN.md §13 lists the specifications and papers cited.
